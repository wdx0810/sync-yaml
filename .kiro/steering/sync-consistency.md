# 核心原则：正向与反向同步的比较逻辑必须一致

这是本项目最重要的功能要求。

## 规则

正向同步（GitLab → K8s）和反向同步（K8s → GitLab）在判断"资源是否有变化、是否需要同步"时，**必须使用完全相同的比较逻辑**。

- 统一使用语义比较 `diff.IsSameContent(cleaner, old, new)`：
  - 先用 `cleaner.Clean` 清洗两边对象（去除 K8s 默认值、运行时字段）。
  - 抽取可比字段后 JSON 归一化（统一数字类型、去掉空值/空容器）再比较。
- **禁止**用纯文本字符串比较（如 `strings.TrimSpace(a) == strings.TrimSpace(b)`）来判断资源是否变化。文本比较会因键顺序、缩进、引号风格、数字格式、cleaner 版本演进而产生大量假变更。
- 比较 GitLab 里存储的 YAML 文件时，要先用 `parser.Parse` 解析成对象，再走 `IsSameContent`；解析失败才退回字符串比较作为兜底。

## 为什么重要

如果两边逻辑不一致，会出现"往返不一致"问题：正向把 GitLab 内容同步到 K8s 后，反向同步再读出来对比，会因为格式差异误报大量变更，导致功能不可用。

## 修改代码时的检查清单

- 任何涉及"判断是否同步/是否有变更"的改动，正向和反向两条路径都要同步修改，保持一致。
- 新增资源类型的字段清洗规则时，确保正反向共用同一个 cleaner。
- 不要在某一侧引入文本比较的捷径。
